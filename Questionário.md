# Questionário para coleta de informações

Este documento reúne perguntas e solicitações para orientar a coleta de dados necessários para concluir as etapas que dependem de informações adicionais.

## 1. Contexto geral do projeto

1. Qual é o objetivo principal do projeto ou etapa atual?
2. Qual é o escopo exato da tarefa em andamento?
3. O trabalho já foi parcialmente concluído? Se sim, o que já foi feito?
4. Há alguma documentação base já existente que deve ser seguida?
5. Existe uma referência de design, linguagem, arquitetura ou padrão que deve ser respeitado?

## 2. Requisitos funcionais

1. Quais funcionalidades precisam ser implementadas ou ajustadas?
2. Há casos de uso específicos que devem ser suportados?
3. A solução precisa suportar entradas, dados ou integrações específicas?
4. Existem regras de negócio que devem ser preservadas?
5. Há algum comportamento esperado que ainda não está claro?

## 3. Requisitos técnicos

1. Qual linguagem de programação ou stack será usada?
2. O projeto já possui arquitetura definida (MVC, modular, plugin, serviço, etc.)?
3. Existe um padrão de organização de pastas, módulos ou componentes a ser seguido?
4. Há alguma restrição de ambiente, IDE, runtime ou sistema operacional?
5. O projeto precisa manter compatibilidade com versões específicas?
6. Existem bibliotecas, dependências ou SDKs obrigatórios?

## 4. Gramática / linguagem / sintaxe

1. Qual é a sintaxe ou gramática que precisa ser suportada?
2. Há exemplos de uso já existentes que servem como referência?
3. Quais elementos da linguagem devem ser reconhecidos: palavras-chave, operadores, comentários, strings, blocos, rotinas, etc.?
4. Existe algum documento oficial ou guia de referência que descreve a sintaxe?
5. O projeto precisa distinguir entre diferentes tipos de tokens ou estruturas da linguagem?

## 5. Escopo do realce de sintaxe (TextMate / VS Code)

1. Quais tipos de tokens devem receber destaque visual?
2. Quais categorias de destaque são desejadas (comentários, strings, palavras-chave, números, funções, variáveis, blocos, operadores)?
3. Existe um tema visual ou paleta de cores já definida para a linguagem?
4. A linguagem possui blocos aninhados, comentários multilinha ou estruturas complexas que exigem regras especiais?
5. Há necessidade de distinguir nomes de rotina, declarações, atributos ou estruturas específicas?

## 6. Estrutura de arquivos e organização

1. Onde os arquivos da linguagem ou da gramática devem ficar no repositório?
2. Existe um padrão de nomeação para extensões, módulos ou arquivos de gramática?
3. A solução precisa gerar arquivos automaticamente ou manter manualmente a gramática?
4. O projeto já possui um local específico para documentação de gramática e referência?

## 7. Dependências e integração

1. Há alguma integração com VS Code, LSP, extensão, parser ou gerador de código?
2. A gramática precisa interagir com ferramentas externas ou módulos do editor?
3. O projeto requer suporte a autocompletar, validação semântica ou diagnósticos?
4. A solução deve funcionar em conjunto com outras linguagens ou gramáticas existentes?

## 8. Regras e prioridades

1. Quais regras têm prioridade maior na interpretação da linguagem?
2. Há ambiguidades sintáticas que precisam ser tratadas com regras específicas?
3. Existe alguma exceção de sintaxe que deve ser tratada antes de regras gerais?
4. Quais padrões devem ser interpretados com maior precisão: blocos, comentários, strings, identificadores ou operadores?

## 9. Validação e confirmação

1. Como a solução será validada?
2. Quais exemplos reais devem ser usados para testar a implementação?
3. O projeto precisa de testes automatizados?
4. Há um critério de aceitação para confirmar que tudo está correto?
5. Quem deve validar a solução final?

## 10. Informações pendentes e bloqueios

1. O que ainda não foi definido?
2. Há algum ponto que depende de uma decisão de arquitetura ou de domínio?
3. Existe algum bloqueio técnico ou de negócio que impeça a conclusão da etapa?
4. Quais informações são essenciais para seguir sem riscos?

## 11. Solicitações de apoio

1. Você pode fornecer exemplos de código ou textos da linguagem para referência?
2. Pode compartilhar documentação, versões anteriores ou materiais de apoio?
3. Pode indicar quais partes do projeto já estão prontas e quais ainda precisam ser refinadas?
4. Pode confirmar o formato esperado da solução final?
5. Pode informar se existe um padrão de nomenclatura ou estilo a ser preservado?

## 12. Observações finais

1. Há alguma informação adicional que gostaria de acrescentar?
2. Há algum ponto importante não coberto por este questionário?
3. Existe alguma prioridade para a execução das etapas?
4. Você deseja que este questionário seja adaptado para um formato mais técnico, mais enxuto ou mais detalhado?

## 14. Observação final

Responda o quanto for possível. Caso alguma pergunta não se aplique ao contexto atual, basta indicar “não se aplica”.

Quando houver dúvidas, priorize respostas que descrevam o comportamento esperado, exemplos concretos e qualquer restrição técnica ou funcional relevante.
